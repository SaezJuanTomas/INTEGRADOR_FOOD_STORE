## API ENDPOINTS DISPONIBLES

### AUTH (Autenticación)
- **POST** `/auth/register` - Registrar nuevo usuario
- **POST** `/auth/login` - Login (retorna JWT + cookie)
- **GET** `/auth/me` - Obtener usuario actual
- **POST** `/auth/logout` - Logout (limpia cookie)

### USUARIOS
- **GET** `/usuarios` - Listar usuarios
- **GET** `/usuarios/{usuario_id}` - Obtener usuario
- **PUT** `/usuarios/{usuario_id}` - Actualizar usuario
- **DELETE** `/usuarios/{usuario_id}` - Soft-delete usuario
- **POST** `/usuarios/{usuario_id}/roles/{rol_codigo}` - Asignar rol
- **DELETE** `/usuarios/{usuario_id}/roles/{rol_codigo}` - Remover rol
- **POST** `/usuarios/{usuario_id}/direcciones` - Crear dirección
- **GET** `/usuarios/{usuario_id}/direcciones` - Listar direcciones
- **GET** `/usuarios/{usuario_id}/direcciones/{direccion_id}` - Obtener dirección
- **PUT** `/usuarios/{usuario_id}/direcciones/{direccion_id}` - Actualizar dirección
- **DELETE** `/usuarios/{usuario_id}/direcciones/{direccion_id}` - Eliminar dirección

### PEDIDOS
- **POST** `/pedidos` - Crear pedido (requiere auth)
- **GET** `/pedidos` - Listar pedidos del usuario (requiere auth)
- **GET** `/pedidos/{pedido_id}` - Obtener detalle de pedido (requiere auth)
- **PATCH** `/pedidos/{pedido_id}/confirmar` - Confirmar pedido
- **PATCH** `/pedidos/{pedido_id}/cancelar` - Cancelar pedido
- **PATCH** `/pedidos/{pedido_id}/estado` - Cambiar estado (admin)
- **GET** `/pedidos/{pedido_id}/historial` - Ver historial de cambios

### PRODUCTOS / CATEGORÍAS / INGREDIENTES
- Endpoints existentes del catálogo (no modificados)

## PRUEBAS RÁPIDAS POR TERMINAL

### 1. Registrar usuario
```powershell
$body = @{
    nombre = "Juan"
    apellido = "Perez"
    email = "juan@test.com"
    celular = "1234567890"
    password = "password123"
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:8000/auth/register" `
    -Method Post -Body $body -ContentType "application/json"
```

### 2. Login
```powershell
$body = @{
    email = "juan@test.com"
    password = "password123"
} | ConvertTo-Json

$response = Invoke-RestMethod -Uri "http://127.0.0.1:8000/auth/login" `
    -Method Post -Body $body -ContentType "application/json"

# Guardar token para siguiente llamada
$token = $response.access_token
```

El login siempre se hace con `email` y `password`.

### 3. Obtener usuario autenticado
```powershell
$headers = @{
    "Authorization" = "Bearer $token"
}

Invoke-RestMethod -Uri "http://127.0.0.1:8000/auth/me" `
    -Method Get -Headers $headers
```

## ARQUITECTURA IMPLEMENTADA

✅ **Usuarios y Roles (IAM simple)**
- Modelo Usuario con soft delete
- N:N relación con Roles (ADMIN, CLIENTE)
- Direcciones de entrega por usuario
- Autenticación JWT simple (sin refresh tokens)

✅ **Pedidos y Estados**
- Estados: PENDIENTE, CONFIRMADO, PREPARANDO, EN_CAMINO, ENTREGADO, CANCELADO
- Snapshots históricos de productos (precio, nombre al momento de compra)
- Historial de cambios de estado
- Transiciones validadas
- Stock descontado al confirmar

✅ **Arquitectura Limpia**
- Services: Lógica de negocio
- Repositories: Acceso a datos
- Routers: HTTP endpoints
- Schemas: DTOs Pydantic
- Soft delete: activo=False (no hard delete)

## TROUBLESHOOTING

### Puerto 8000 ya está en uso
```powershell
# Ver qué proceso usa el puerto
netstat -ano | Select-String ":8000"

# (Opcional) matar proceso por PID
Stop-Process -Id <PID> -Force

# Levantar backend en 8000
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

### PostgreSQL no conecta
```powershell
# Verificar que Docker está corriendo
docker compose ps

# Si falla, recrear:
docker compose down
docker compose up -d

# Verificar puerto de PostgreSQL
netstat -ano | Select-String ":5432"
```

### Módulos no importan
```powershell
# Reinstalar dependencias
pip install -r requirements.txt --force-reinstall

# O activar venv
.\.venv\Scripts\Activate.ps1
```

## NOTAS

- Los usuarios nuevos se crean con rol CLIENTE automáticamente (via frontend/backend)
- Los roles ADMIN y Estados de Pedido se crean automáticamente al iniciar la app
- Las direcciones pueden marcarse como "principal"
- Al confirmar un pedido, se descuenta stock automáticamente
- No hay refresh tokens (JWT válido 24h)
- Usar cookies httponly para seguridad en navegador
- Para endpoints de admin (cambiar estado), implementar rol_checker en frontend si es necesario
- El acceso al frontend usa el email registrado, por ejemplo `admin@test.com` o `cliente@test.com`
